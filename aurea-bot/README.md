# Aurea — Telegram-бот онлайн-записи

Бот для онлайн-записи в клинику эстетической косметологии **Aurea** (Москва).
Запись в пару шагов, напоминания о визите, уведомления администратору.
Все данные хранятся **локально в SQLite** — никаких зарубежных сервисов и
внешних API (требование 152-ФЗ, хостинг на сервере в РФ).

## Возможности

- Экран согласия на обработку ПДн (152-ФЗ) **до** любого сбора данных.
- Запись: услуга → дата → время → имя → телефон → подтверждение.
- Свободные слоты рассчитываются с учётом рабочих часов, занятых записей и
  прошедшего времени. Окно записи — с завтрашнего дня до +14 дней.
- Проверки: формат телефона (РФ), имя (2–50 символов, без ссылок), защита от
  записи в прошлое и в занятый слот (в т.ч. от гонки), лимит 3 активные записи.
- «Мои записи» с отменой (освобождает слот).
- Напоминания клиенту за 24 ч и за 2 ч (APScheduler).
- Админу: уведомление о новой записи, `/bookings` (список), `/test_reminder`.

## Стек

Python 3.11+, aiogram 3.x (роутеры + FSM), aiosqlite, APScheduler,
python-dotenv, zoneinfo. Запуск через long polling.

## Структура

```
aurea-bot/
  config.py              — чтение .env, константы
  data/
    services.json        — услуги и цены (единый источник, формат как на сайте)
    texts.py             — ВСЕ тексты бота (русский)
    schedule.py          — рабочие часы, слоты, окно записи, напоминания
    clinic.py            — реквизиты клиники
    __init__.py          — загрузчик services.json
  core/                  — бизнес-слой, НЕ зависит от aiogram
    db.py                — схема SQLite и подключение
    bookings.py          — создание/отмена/список записей, слоты, напоминания
    slots.py             — генерация свободных слотов
    consent.py           — согласие на обработку ПДн
    validation.py        — валидация телефона и имени
  bot/                   — Telegram-слой (aiogram)
    main.py              — точка входа, polling + планировщик
    keyboards.py, states.py, reminders.py
    handlers/            — start, menu, booking, my_bookings, admin, fallback
  tests/selfcheck.py     — самопроверка (8 пунктов чек-листа)
```

Бизнес-слой (`core/`) отделён от Telegram-слоя: функции в `core/` не знают про
aiogram. Это позволит позже навесить HTTP API для сайта **без переписывания**
логики (см. TODO в `core/bookings.py`). Сам эндпоинт сейчас не реализован.

## Установка

1. Получите **BOT_TOKEN** у [@BotFather](https://t.me/BotFather): команда
   `/newbot`, задайте имя и username — в ответ придёт токен.
2. Узнайте свой **ADMIN_CHAT_ID** — chat_id, куда будут приходить уведомления о
   новых записях. Проще всего: запустите бота и напишите ему `/id` — он пришлёт
   ваш числовой id. Либо напишите боту [@userinfobot](https://t.me/userinfobot).
3. Установка зависимостей:

   ```bash
   cd aurea-bot
   python -m venv .venv
   source .venv/bin/activate        # Windows: .venv\Scripts\activate
   pip install -r requirements.txt
   ```

4. Заполните `.env`:

   ```bash
   cp .env.example .env
   # откройте .env и впишите BOT_TOKEN и ADMIN_CHAT_ID (и, при необходимости,
   # реальные POLICY_URL и CONSENT_URL)
   ```

## Запуск

```bash
python -m bot.main
```

Бот стартует в режиме long polling и запускает планировщик напоминаний.

Полная инструкция «как подключить к реальному боту, назвать его и запустить
24/7 на сервере в РФ» — в **[DEPLOY.md](DEPLOY.md)** (BotFather, `.env`,
systemd-сервис `deploy/aurea-bot.service`).

## Где что менять (без правки кода логики)

- **Услуги и цены** — `data/services.json` (поля: `id`, `name`,
  `price_label`, `duration_min`, `note`). Формат совпадает с сайтом.
- **Тексты** — `data/texts.py` (все формулировки на русском).
- **Расписание** — `data/schedule.py` (рабочие часы по дням, длина слота,
  окно записи, время напоминаний, лимит записей).
- **Реквизиты клиники** — `data/clinic.py` (бренд, адрес, часы, телефон,
  email, лицензия, дисклеймер, ссылка на карты).

## Важно перед реальным запуском

- Это **демо-данные**: телефон `+7 (900) 000-00-00`, email `hello@aurea.ru`
  и ссылки `POLICY_URL`/`CONSENT_URL` — **замените на реальные**.
- Публиковать бота на людей можно **только** после подстановки реальных
  **POLICY_URL** (политика конфиденциальности) и **CONSENT_URL** (согласие на
  обработку ПДн) — это требование 152-ФЗ.
- Размещайте бота и БД на **сервере в РФ** (локализация персональных данных).
- Бот осознанно **не собирает** медицинские данные (жалобы, диагнозы).

## Соответствие законам РФ

- **152-ФЗ**: согласие до сбора данных; локальное хранение (РФ-хостинг);
  ссылки на политику и отдельный документ согласия; собираем минимум — имя,
  телефон, услуга, дата.
- **Реклама мед. услуг**: без обещаний результата и гарантий; дисклеймер
  «Имеются противопоказания. Необходима консультация специалиста.» — в
  подтверждении записи, в услугах и в контактах.
- **168-ФЗ**: весь интерфейс на русском языке.

## Самопроверка

```bash
python tests/selfcheck.py
```

Прогоняет на временной БД (без токена и сети) 8 пунктов чек-листа:

1. Проект ставится, модули импортируются без ошибок.
2. Согласие сохраняется/проверяется; без согласия запись недоступна.
3. Полный сценарий записи проходит до создания записи.
4. Занятый слот не предлагается; прошедшие/нерабочие даты и времена скрыты.
5. Некорректный телефон отклоняется, корректный нормализуется к `+7`.
6. После подтверждения запись видна в «Мои записи» и уходит уведомление админу.
7. Отмена записи освобождает слот.
8. Планировщик напоминаний запускается без ошибок; логика напоминаний верна.

Код выхода `0` — все проверки прошли.
